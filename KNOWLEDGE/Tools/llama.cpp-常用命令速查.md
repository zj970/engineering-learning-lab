# llama.cpp 常用命令速查

## 本质

这篇文档不是安装教程，也不是完整参数手册。  
它的作用是：当你已经装好 `llama.cpp`、准备好模型文件之后，能够快速找到“当前应该用哪条命令”。

如果说 [llama.cpp-入门指南](/home/zj970/ai-study/KNOWLEDGE/Tools/llama.cpp-入门指南.md) 负责回答“这是什么”，那么这篇文档主要负责回答“现在怎么用”。

---

## 原理

`llama.cpp` 常见的高频命令可以按职责分成三类：

### 1. 设备与环境确认

这类命令用于确认：

- 程序能不能直接找到
- 动态库能不能正常加载
- CUDA 设备有没有被识别到

### 2. 文本生成

这类命令主要使用 `llama-cli`。  
它适合：

- 普通问答
- 代码生成
- 模型可用性验证

### 3. 向量生成与服务化

这类命令分别对应：

- `llama-embedding`：把文本转成向量
- `llama-server`：把模型作为本地服务跑起来

所以你在使用前先判断当前目标是什么：

- 想看自然语言回答，用 `llama-cli`
- 想得到向量，用 `llama-embedding`
- 想提供浏览器或接口服务，用 `llama-server`

## 流程

使用这些命令时，建议固定按下面顺序检查：

### 第一步：确认命令和动态库环境

先确认：

- `PATH` 是否已经包含 `llama.cpp` 的 `bin` 目录
- `LD_LIBRARY_PATH` 是否已经包含 `llama.cpp` 的 `lib` 目录

如果这一步没配好，常见现象是：

- 输入 `llama-cli` 提示命令找不到
- 程序能启动，但报 `.so` 找不到

### 第二步：确认设备

如果你希望使用 NVIDIA GPU，先确认 CUDA 设备是否被识别。  
否则后面推理慢，或者你以为在用 GPU，实际却只跑在 CPU。

### 第三步：按模型类型选择命令

- chat / instruct 模型：通常用 `llama-cli` 或 `llama-server`
- coder 模型：通常也用 `llama-cli`
- embedding 模型：用 `llama-embedding`

### 第四步：只关注最关键参数

新手不需要一开始就记住所有参数。  
最先掌握下面几个就够了：

- `-m`：模型路径
- `-ngl`：尝试放到 GPU 的层数
- `-n`：最多生成多少 token
- `--port`：服务监听端口

## 示例

### 1. 查看可用设备

```bash
llama-cli --list-devices
```

用途：
- 检查 `llama.cpp` 是否能正常启动
- 检查 CUDA 设备是否被识别

你应该重点看什么：
- 是否列出了 `CUDA0`
- 是否显示显卡名称、显存和可用显存

容易误解的点：
- 能列出设备，不代表模型一定能完整放进显存
- 如果这里没有 `CUDA0`，后面的 `-ngl` 也不会真正走 CUDA 加速

### 2. 使用 chat 模型做普通问答

```bash
llama-cli \
  -m ~/models/chat/qwen2.5-7b-instruct-q4_k_m.gguf \
  -ngl 20 \
  -p "请用三句话解释什么是操作系统" \
  -n 256
```

用途：
- 快速验证 chat 模型是否能正常回答问题
- 本地做最小问答测试

关键参数：
- `-m`：指定实际要加载的 `.gguf` 模型文件
- `-ngl 20`：尝试把 20 层放到 GPU，适合先做保守验证
- `-p`：直接给一段提示词
- `-n 256`：限制最多生成 256 个 token，避免无限生成

容易误解的点：
- `-n 256` 不是上下文窗口，它只是这次回答最多写多长
- 如果回答中途停止，很多时候是 `-n` 限制到了，不是模型坏了

### 3. 使用 coder 模型做编程问答

```bash
llama-cli \
  -m ~/models/coder/qwen2.5-coder-7b-instruct-q4_k_m.gguf \
  -ngl 20 \
  -p "请写一个 Java 函数判断字符串是否为回文，并解释时间复杂度" \
  -n 256
```

用途：
- 生成代码
- 解释代码
- 做最小编程能力验证

关键参数：
- 参数形式和 chat 模型几乎一样，主要区别在于模型文件不同

容易误解的点：
- coder 模型不是“另一个程序”，只是“另一个更擅长代码的模型”
- 如果你换成 chat 模型执行同样命令，也能回答，但代码能力和风格通常不同

### 4. 使用 embedding 模型生成向量

```bash
llama-embedding \
  -m ~/models/embed/Qwen3-Embedding-4B-Q4_K_M.gguf \
  -ngl 10 \
  -p "什么是操作系统"
```

用途：
- 把文本转成 embedding 向量
- 为知识库检索做准备

关键参数：
- `-m`：embedding 模型路径
- `-ngl 10`：先给一个相对保守的 GPU 卸载层数
- `-p`：要编码成向量的文本

容易误解的点：
- 正常输出是一长串浮点数，不是自然语言答案
- 它的职责是“编码”，不是“回答”

### 5. 启动本地服务

```bash
llama-server \
  -m ~/models/chat/qwen2.5-7b-instruct-q4_k_m.gguf \
  -ngl 20 \
  --port 8080
```

用途：
- 把模型作为本地服务运行
- 提供浏览器访问和接口调用入口

关键参数：
- `-m`：加载哪个模型
- `-ngl`：尝试用多少层走 GPU
- `--port 8080`：服务监听在本机 `8080` 端口

容易误解的点：
- `llama-server` 不是“更强的模型”，只是另一种运行方式
- 能启动服务，不代表接口调用参数一定正确，还要看具体请求格式

### 6. 常见参数速查

| 参数 / 概念 | 作用 | 最常见误解 |
| --- | --- | --- |
| `-m` | 指定模型文件路径 | 把模型仓库页面当成模型路径 |
| `-ngl` | 尝试把部分层卸载到 GPU | 以为越大一定越好，忽略显存限制 |
| `-n` | 最大生成 token 数 | 误认为上下文窗口大小 |
| `--port` | 指定服务监听端口 | 误认为只写了端口就等于接口可直接用了 |
| `PATH` | 让系统能直接找到命令 | 和动态库加载混为一谈 |
| `LD_LIBRARY_PATH` | 让程序运行时能找到 `.so` | 以为只配 `PATH` 就足够 |

### 7. 最常见的几个误区

#### 误区一：命令能执行，说明环境已经完全正常

不一定。  
如果动态库路径没配好，程序仍然可能在真正启动时报：

```text
error while loading shared libraries
```

#### 误区二：`PATH` 和 `LD_LIBRARY_PATH` 是同一件事

不是。  
`PATH` 负责找可执行文件，`LD_LIBRARY_PATH` 负责找运行时依赖库。

#### 误区三：embedding 模型“没有回答我”

这是正常现象。  
embedding 模型本来就不会输出自然语言解释，它输出的是向量。

#### 误区四：`-n` 越小，说明上下文越小

不是。  
`-n` 控制的是这次生成多少 token，不是模型能看多长上下文。

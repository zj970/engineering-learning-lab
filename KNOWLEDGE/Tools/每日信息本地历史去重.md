# 每日信息本地历史去重

## 本质

每日信息脚本的去重分两层：

- 本次抓取内部去重：解决同一次运行中多个来源或同一来源重复返回的问题。
- 本地历史去重：解决今天抓到的内容在过去日报中已经出现过的问题。

本地历史去重的核心不是重新抓取网络，而是把 `data/daily_info/*.md` 当作本地已读索引，生成新日报时先排除历史已出现条目。

---

## 原理

历史日报中的条目格式为：

```md
- [标题](链接)
```

脚本从历史 markdown 中提取标题和链接，并复用现有规范化规则：

- 标题：去 HTML、转小写、去标点、合并空白。
- 链接：统一 scheme / host 小写，去掉 query / fragment，去掉末尾 `/`。

然后用 `(normalized_title, normalized_link)` 作为本地历史 key。生成目标日期时，会排除同名日期文件，避免重新生成当天日报时把自己当成历史重复源。

---

## 流程

1. 扫描 `data/daily_info/*.md`。
2. 跳过当前输出日期文件，例如生成 `2026-04-26.md` 时不读取 `2026-04-26.md`。
3. 从历史文件中提取 `- [标题](链接)` 条目。
4. 对新抓取条目执行同样的标题和链接规范化。
5. 如果新条目的 key 已存在于历史 key 集合，则从本次输出中移除。
6. 在日报概览中记录 `本地历史去重移除` 数量。

---

## 问题

如果只做本次抓取内部去重，历史文章可能在多天日报中反复出现，尤其是 RSS 源保留较长列表时更明显。

本地历史去重可以降低重复阅读成本，但它也有取舍：

- 使用标题和链接共同判断，误删风险较低。
- 如果同一文章标题或链接路径发生变化，可能不会被识别为重复。
- 如果未来希望更激进去重，可以增加仅按链接去重或标题相似度判断，但误删风险会升高。

---

## 个人理解

日报类脚本的价值不只是“抓到更多”，而是“减少重复噪声”。本地历史去重让 `data/daily_info/` 从静态输出目录变成轻量历史索引，适合个人学习场景下长期积累和复盘。

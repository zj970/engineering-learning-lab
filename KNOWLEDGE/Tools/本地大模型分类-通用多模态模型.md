# 本地大模型分类：通用多模态模型

## 本质

通用多模态模型不是单纯的 chat 模型，也不是 coder 或 embedding 模型。  
它的核心特征是能同时处理文本与其他模态输入，例如图片、音频，部分模型还支持视频。

这类模型的定位通常是“通用助手”，适合做理解、分析、总结和交互，而不是只专注写代码或生成向量。

## 原理

和纯文本 chat 模型相比，多模态模型通常多了这些组件：

- processor 或前处理器
- vision encoder
- audio encoder
- multimodal projector

因此它的输入链路不只是“文本 token -> LLM”，而是“多模态数据 -> 编码/投影 -> LLM”。

## 常见职责

通用多模态模型通常擅长：

- 图片理解
- OCR 和文档理解
- 图表解释
- 音频转写与理解
- 视频内容概述
- 多轮对话
- 结合上下文做推理

Gemma 4 12B IT 就属于这一类。

## 和其他分类的区别

- chat：主要处理文本问答
- coder：主要处理代码生成和代码解释
- embedding：主要把文本转成向量
- multimodal：主要处理多模态输入并输出自然语言

## 判断方法

看到下面这些信号，通常就该单独归到“通用多模态”：

1. model card 明确写了 image / audio / video 支持。
2. 加载时需要 `AutoProcessor`，而不是只用纯文本 tokenizer。
3. 输入消息里需要按模态顺序组织内容。
4. 同一模型既能对话，又能看图、听音频、读文档。

## 个人理解

这类模型最容易被误分到 `chat`，因为它最终也会输出自然语言。  
但它的价值不只在“会聊天”，而在于能把不同模态的信息统一进一个推理框架里。

对学习分类来说，最实用的做法是先按职责分四类：

- chat
- coder
- embedding
- multimodal

这样后面看模型仓库、推理脚本和部署方式时，会更清楚。

# llama.cpp 入门指南

## 本质

`llama.cpp` 的本质不是“大模型本身”，而是一个本地运行大模型的框架。  
它负责把已经准备好的模型文件加载到 CPU、GPU 或两者混合环境中，并提供命令行、服务端和 embedding 等运行方式。

如果把模型比作“数据本体”，那么 `llama.cpp` 更像“本地推理引擎”。

---

## 原理

### 1. `llama.cpp` 运行的不是模型仓库，而是模型文件

在日常使用中，真正被加载的是 `.gguf` 文件，而不是 Hugging Face 或 ModelScope 上的整个模型页面。

例如：

- chat / instruct 模型：负责自然语言回答
- coder 模型：负责代码生成、解释和辅助编程
- embedding 模型：负责把文本转成向量
- multimodal 模型：负责文本、图像、音频等多模态理解与回答

### 2. `GGUF` 是本地推理常见文件格式

`GGUF` 可以理解为适合 `llama.cpp` 加载的模型封装格式。  
它把模型权重、元数据和部分运行信息组织在一个统一文件里，便于本地推理框架直接读取。

### 3. 量化是为了降低显存和内存压力

你常看到的：

- `Q4_K_M`
- `Q8_0`

本质上都是量化形式。  
量化后的模型通常更小，更适合本地设备运行，但不同量化格式会在体积、速度和效果之间做取舍。

### 4. GPU / CPU 混合推理是本地常见方案

并不是模型只能“全在 GPU”或者“全在 CPU”上运行。  
在 `llama.cpp` 里，常见做法是把一部分层放到 GPU，剩余部分由 CPU 参与，这就是常说的混合推理。

参数 `-ngl` 就是这个思路的典型体现：

- `-ngl` 越高，表示尝试放更多层到 GPU
- 显存不够时，可以降低它

## 流程

从零理解 `llama.cpp`，可以按下面这条最小链路来看：

### 第一步：准备模型文件

你需要先有一个真实可用的 `.gguf` 文件。  
没有模型文件，`llama.cpp` 本身无法完成推理。

### 第二步：选择运行方式

`llama.cpp` 常见的运行入口有三个：

#### `llama-cli`

最直接的交互方式。  
适合：

- 本地问答
- 代码生成
- 快速验证模型是否可用

#### `llama-server`

把模型作为本地服务启动。  
适合：

- 浏览器访问 Web UI
- 通过 OpenAI 兼容接口调用
- 给其他程序接入

#### `llama-embedding`

专门用于生成文本向量。  
适合：

- 知识库检索
- 语义相似度计算
- RAG 系统前置检索

### 第三步：验证链路

一个本地链路是否真正跑通，通常至少需要验证三件事：

1. 模型能被加载
2. 推理或向量生成能正常执行
3. 输出形式符合模型类型预期

## 最小使用示例

下面只放最小必要示例，不展开所有参数。

### 1. chat 模型

```bash
llama-cli \
  -m ~/models/chat/qwen2.5-7b-instruct-q4_k_m.gguf \
  -ngl 20 \
  -p "请用三句话解释什么是操作系统" \
  -n 256
```

适合：

- 普通问答
- 文档理解
- 知识库最终回答

### 2. coder 模型

```bash
llama-cli \
  -m ~/models/coder/qwen2.5-coder-7b-instruct-q4_k_m.gguf \
  -ngl 20 \
  -p "请写一个 Java 函数判断字符串是否为回文，并解释时间复杂度" \
  -n 256
```

适合：

- 写代码
- 解释代码
- 辅助调试

### 3. embedding 模型

```bash
llama-embedding \
  -m ~/models/embed/Qwen3-Embedding-4B-Q4_K_M.gguf \
  -ngl 10 \
  -p "什么是操作系统"
```

这类命令的正常输出不是自然语言，而是一串浮点数向量。  
这说明文本已经被成功编码成 embedding。

## GUI 与服务化

`llama.cpp` 不只有命令行模式。  
它还可以通过 `llama-server` 提供本地服务和基础 Web UI。

最小示例：

```bash
llama-server \
  -m ~/models/chat/qwen2.5-7b-instruct-q4_k_m.gguf \
  -ngl 20 \
  --port 8080
```

启动后，可以在浏览器访问：

```text
http://localhost:8080
```

这是一种最轻量的 GUI 使用方式。  
同时，`llama-server` 还可以提供 OpenAI 兼容接口，方便其他程序调用。

## 常见问题

### 1. 为什么模型已经安装成功，但运行时报找不到 `.so`？

这通常不是模型问题，而是动态库搜索路径没有配置。  
如果把 `llama.cpp` 安装到了用户目录，往往还需要配置：

```bash
export LD_LIBRARY_PATH="$HOME/.local/llama.cpp/lib:${LD_LIBRARY_PATH:-}"
```

### 2. 为什么已经能执行 `llama-cli`，却还要配置 `PATH`？

`PATH` 解决的是“命令能不能直接找到”。  
`LD_LIBRARY_PATH` 解决的是“运行时依赖库能不能找到”。  
这两个问题不是一回事。

### 3. 为什么 embedding 模型看起来“没有回答”？

因为 embedding 模型本来就不负责输出自然语言回答。  
它的正常输出是一串向量。

### 4. 为什么回答中途停了，是上下文不够吗？

不一定。  
如果命令里写了：

```bash
-n 128
```

更常见的原因是“最大生成长度到了”，而不是上下文窗口太小。

### 5. 下载了 `.gguf` 文件就一定能用吗？

不一定。  
你需要确认下载的是完整模型，而不是词表类文件。  
像 `ggml-vocab-*.gguf` 这类文件不能直接当作完整聊天模型来用。

## 推荐组合

如果你想在一台普通 Linux 机器上快速形成一个本地可用组合，可以按职责分工：

### 1. 编程模型

- `Qwen2.5-Coder-7B-Instruct Q4_K_M`

用途：

- 代码生成
- 代码解释
- 编程辅助

### 2. 知识库回答模型

- `Qwen2.5-7B-Instruct Q4_K_M`

用途：

- 文档问答
- 知识库最终回答
- 通用中文对话

### 3. 检索模型

- `Qwen3-Embedding-4B Q4_K_M`

用途：

- 文档向量化
- 问题向量化
- 检索相关内容

这四者的关系可以简单理解为：

- coder：负责代码
- chat：负责回答
- embedding：负责检索
- multimodal：负责多模态理解

## 个人理解

理解 `llama.cpp` 最容易犯的错误，是把它当成“另一个模型名字”。  
实际上它更像一个本地运行平台：

- 模型文件决定“你能做什么”
- `llama.cpp` 决定“你怎么把它跑起来”

如果先建立这层认识，再去看 `llama-cli`、`llama-server`、`GGUF`、量化和 embedding，就会清晰很多。

对初学者来说，真正有效的顺序通常不是先记住所有参数，而是先回答这几个问题：

1. 我现在跑的是哪一类模型？
2. 我想得到的是自然语言回答，还是向量？
3. 我现在是在用 CLI、Server，还是 embedding 工具？
4. 当前问题出在命令找不到、动态库找不到，还是模型文件本身不对？

一旦这几个问题能分清，`llama.cpp` 的学习成本会下降很多。

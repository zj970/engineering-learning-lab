# 每日信息工作流设计

## 本质

把“刷资讯”变成“有主题的信息采集、初筛与沉淀”。目标不是覆盖更多网站，而是每天稳定获得少量高价值输入，并保存在本地可复用的 Markdown 中。

## 原理

整个链路分成四步：

1. 维护固定主题和信息源。
2. 用本地脚本抓取 RSS / HTML 标题。
3. 按主题和关键词做初步分类与优先级判断。
4. 先做自动去重，再把抓取异常从主列表分离，单独汇总。

## 流程

- 输入：主题配置 `tools/daily_info/sources.json`
- 处理：脚本 `tools/daily_info/generate_daily_info.py`
- 模板：`TEMPLATES/daily_info/daily-info.md`
- 输出：`data/daily_info/YYYY-MM-DD.md`

## 社区源扩展策略

- 社区源既可以嵌入原主题，也可以单独成类。
- 对 `linux.do` 这类站点，放进 `工程效率工具` 可以帮助你捕捉工具、Linux、AI 混合讨论。
- 同时增加独立的 `中文技术社区` 分类，可以把高热度但噪音较大的来源集中管理，避免污染主主题流。

## 当前中文技术社区分类

- LinuxDo
- V2EX
- 掘金首页
- 少数派
- 博客园首页

## 常见问题

- 社区类源噪音通常高于官方源和个人博客。
- 某些社区接口不是标准 RSS，后续可能需要更有针对性的解析。
- 同一来源放进两个分类时，后续可能需要全局去重配合。

## 个人理解

真正可用的信息系统，不是把所有来源塞进一个桶，而是把不同“信号类型”的来源分层管理。社区源适合发现问题和热点，但不应该淹没主线学习主题。

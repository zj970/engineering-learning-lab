# 会话记录

## 基本信息

- 时间：2026-07-01
- 主题：Fcitx5 候选框在 VS Code/IDEA 中为蓝色、浏览器中为灰色的处理

---

## 问题

用户反馈：

- VS Code 候选框为蓝色，终端/浏览器为灰色。
- IDEA 中候选框也为蓝色。
- 将 `classicui.conf` 中 `UseAccentColor=False` 后无效。

---

## 分析

上一轮只修改 Classic UI 强调色无效，说明蓝色候选框不是 Classic UI 的 accent color 单点问题。

新的现象是：

```text
VS Code 蓝色
IDEA / Android Studio 蓝色
Firefox 浏览器灰色
```

这说明不同应用很可能走了不同的 Fcitx5 UI 前端。KDE Wayland 下，Fcitx5 同时启用了：

- Classic User Interface
- KDE Input Method Panel，即 `kimpanel`
- DBus Virtual Keyboard

其中 `kimpanel` 会使用 KDE/Plasma 风格，候选高亮更容易呈现蓝色。浏览器仍为灰色，说明浏览器很可能没有走这条面板绘制路径。

---

## 处理

已保留上一轮设置：

```text
~/.config/fcitx5/conf/classicui.conf
UseAccentColor=False
```

新增处理：

```text
~/.config/fcitx5/config
DisabledAddons=kimpanel
```

随后执行受控重启：

```bash
fcitx5-remote -e
fcitx5 --disable kimpanel -d
```

启动日志确认：

```text
Override Disabled Addons: {kimpanel}
Loaded addon classicui
```

日志中未再看到 `Loaded addon kimpanel`，说明当前会话已经强制使用 Classic UI 绘制候选框。

---

## 关键知识点

- `UseAccentColor=False` 只影响 Classic UI；如果候选框实际由 KDE Input Method Panel 绘制，这个配置不会生效。
- `fcitx5-remote -r` 能重载部分配置，但不能可靠地切换 addon 启停状态；禁用 `kimpanel` 这类 addon 后，需要重启 Fcitx5。
- `fcitx5-diagnose` 的 addon 汇总更偏“安装/可用 addon”诊断，不能完全替代启动日志判断运行时 override。
- 当前最可靠证据是 Fcitx5 启动日志中的 `Override Disabled Addons: {kimpanel}` 和 `Loaded addon classicui`。

---

## 我的薄弱点

- 起初把蓝色候选框归因到 Classic UI 的 accent color，忽略了 KDE Input Method Panel 接管绘制的可能。
- 对 Fcitx5 的 `reload` 与 `restart` 边界需要更敏感：addon 启停不是普通运行时配置。

---

## 收获

- 当不同应用候选框配色不一致时，应优先判断“候选框由哪个 UI 前端绘制”，而不是先调主题颜色。
- KDE Wayland 输入法链路中，`classicui` 与 `kimpanel` 可以同时存在，实际显示效果可能随应用和输入协议变化。
- 用户验证后确认 VS Code/IDEA 候选框已恢复正常，说明蓝色候选框根因是 `kimpanel` 接管绘制。

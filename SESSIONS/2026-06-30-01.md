## 分析

本次通过 `journalctl --list-boots` 先确认启动边界：

- 上次启动：`2026-06-30 22:10:58` 到 `2026-06-30 22:21:35`
- 本次启动：`2026-06-30 22:21:50` 开始

上次启动的关键日志：

```text
Jun 30 22:11:09 kwin_wayland_wrapper[1489]:
Failed to load library for addon rime on "/usr/lib/fcitx5/librime.so".
Error: /usr/lib/librime.so.1: undefined symbol:
_ZNK6opencc9Converter7ConvertERKNSt7__cxx1112basic_stringIcSt11char_traitsIcESaIcEEE

Jun 30 22:11:09 kwin_wayland_wrapper[1489]:
Could not load addon rime
```

这不是 Rime 输入法逻辑运行后崩溃，而是 Fcitx5 加载 Rime 插件时，动态链接阶段失败。`librime.so.1` 依赖的 `opencc::Converter::Convert(...)` 符号在当前 `opencc` 库中无法解析，属于动态库 ABI/符号不匹配。

包管理日志显示：

```text
2026-06-29 22:49:44 upgraded opencc (1.3.1-1 -> 1.3.2-1)
2026-06-30 22:11:26 upgraded librime (1:1.17.0-1 -> 1:1.17.0-3)
```

因此合理链路是：

```text
opencc 先升级到 1.3.2
-> 旧 librime 1:1.17.0-1 与新 opencc ABI 不匹配
-> Fcitx5 加载 Rime 插件失败
-> 后续 pacman 升级 librime 到 1:1.17.0-3
-> 重启后 Fcitx5/Rime 使用新 librime
-> Rime 正常加载
```

## 关键知识点

- 输入法插件加载失败要先区分“进程崩溃”和“动态链接失败”。
- `undefined symbol` 通常说明运行时加载到的动态库与编译时预期 ABI 不一致。
- Arch 这类滚动发行版中，`opencc`、`librime`、`fcitx5-rime` 这类相互依赖包如果没有完整同步升级，容易出现短暂 ABI 不匹配。
- 排查输入法启动问题时，需要同时看用户日志和系统日志：

```bash
journalctl --user -b -1 --no-pager | rg -i 'rime|fcitx|undefined|symbol|coredump'
journalctl -b -1 --no-pager | rg -i 'rime|fcitx|undefined|symbol|coredump'
```

- 对动态库问题，可以用：

```bash
ldd -r /usr/lib/fcitx5/librime.so
ldd -r /usr/lib/librime.so.1
pacman -Qo /usr/lib/fcitx5/librime.so /usr/lib/librime.so.1 /usr/lib/libopencc.so.1.3
```

## 我的薄弱点

- 容易把桌面日志里的 `crash`、`SIGTERM`、`Could not load addon` 混在一起看，需要按时间线和进程边界拆开。
- 对动态库 ABI 问题，需要建立“包升级日志 -> 运行时链接错误 -> 当前链接验证”的证据链，而不是只看最终是否能用。

---

## 收获

- 本次问题根因不是 Rime 配置错误，也不是输入方案文件损坏，而是 `librime` 与 `opencc` 的 ABI/符号不匹配。
- `librime 1:1.17.0-3` 升级后与 `opencc 1.3.2-1` 匹配，本次重启后 Rime 正常加载。
- `coredumpctl` 没有 Rime/Fcitx core dump，支持“加载失败而非崩溃”的判断。

## 后续任务

- 遇到类似输入法异常时，优先执行：

```bash
journalctl --list-boots
journalctl --user -b -1 --no-pager | rg -i 'rime|fcitx|undefined|symbol'
rg 'librime|opencc|fcitx5-rime' /var/log/pacman.log
ldd -r /usr/lib/fcitx5/librime.so
```

- 如果再次出现 ABI 不匹配，优先完整升级相关包并重启用户会话或系统。

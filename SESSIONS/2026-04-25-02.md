# 会话记录

## 基本信息

- 时间：2026-04-25
- 主题：`lineage_cas-userdebug` lunch 失败与三段式目标修正

---

## 问题

用户在 `/home/zj970/android/cas-lineage21/source` 中执行 `source build/envsetup.sh` 后运行 `lunch`，手动输入：

```bash
lineage_cas-userdebug
```

结果报错：

```text
Invalid lunch combo: lineage_cas-userdebug
Valid combos must be of the form <product>-<release>-<variant>
```

用户疑问：这是不是 Android 14 源码编译？为什么没有可选产品？

---

## 分析

当前源码树确认为 `LineageOS 21 / Android 14`：

- manifest 默认 AOSP tag：`android-14.0.0_r67`
- 默认 Lineage 分支：`lineage-21.0`
- `PLATFORM_VERSION=14`

问题不是“不是 Android 14”，而是当前构建系统的 `lunch` 规则要求三段式目标：

```bash
<product>-<release>-<variant>
```

当前 release 配置来自：

```bash
vendor/lineage/vars/aosp_target_release
```

内容为：

```text
aosp_target_release=ap2a
```

因此 `cas` 正确 lunch 目标应为：

```bash
lineage_cas-ap2a-userdebug
```

另外，排查中发现用户级 Go 配置：

```bash
/home/zj970/.config/go/env
```

设置了：

```bash
GO111MODULE=on
```

这会干扰 Android 源码树内置 Go 工具，导致：

```text
package unsafe is not in std
```

临时设置：

```bash
export GO111MODULE=off
```

后，再执行：

```bash
lunch lineage_cas-ap2a-userdebug
```

验证成功，输出包含：

- `PLATFORM_VERSION=14`
- `LINEAGE_VERSION=21.0-20260425-UNOFFICIAL-cas`
- `TARGET_PRODUCT=lineage_cas`
- `TARGET_BUILD_VARIANT=userdebug`
- `TARGET_ARCH=arm64`

---

## 关键知识点

- Android 14 / LineageOS 21 源码树中，`lunch` 可能要求 `<product>-<release>-<variant>` 三段式目标。
- 当前 `cas` 的正确目标是 `lineage_cas-ap2a-userdebug`。
- `ap2a` 来自 `vendor/lineage/vars/aosp_target_release` 和 `vendor/lineage/release/release_config_map.mk`。
- `lunch` 菜单无法显示，不一定是没有产品，也可能是 `get_build_var COMMON_LUNCH_CHOICES` 失败。
- 用户级 Go 配置会污染 Android 构建环境，尤其是 `GO111MODULE=on`。

---

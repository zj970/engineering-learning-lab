# 会话记录

## 基本信息

- 时间：2026-07-01
- 主题：排查 NanoPi NEO 能 ping IP 但 git 无法解析 github.com

---

## 问题

用户在 NanoPi NEO 上执行：

```bash
git clone https://github.com/friendlyarm/WiringNP
```

报错：

```text
fatal: unable to access 'https://github.com/friendlyarm/WiringNP/': Could not resolve host: github.com
```

同时 `ping 8.8.8.8` 正常，说明 IP 连通性存在；用户尝试修改 `/etc/resolv.conf`、`/etc/resolvconf.conf` 和 `/etc/dhcp/dhclient.conf`，但 `/etc/resolv.conf` 仍由 `resolvconf` 生成，并保持：

```text
nameserver 192.168.1.1
nameserver fdd4:aed7:8094::1
search lan
```

---

## 分析

当前故障应先定位为 DNS 解析链路问题，而不是 GitHub 仓库地址或网络出口完全不可用：

- `ping 8.8.8.8` 成功，表示默认路由、网关和公网 IP 连通基本正常。
- `git clone` 报 `Could not resolve host: github.com`，失败点在域名解析阶段，还没有进入 HTTPS 连接和 Git 协议阶段。
- `/etc/resolv.conf` 明确提示由 `resolvconf(8)` 动态生成，直接编辑该文件会被覆盖。
- 用户在 shell 中输入 `supersede domain-name-servers ...;` 报 `command not found`，说明这是 `dhclient.conf` 配置语句，不是 shell 命令。
- 修改 `/etc/resolvconf.conf` 后没有反映到最终 `/etc/resolv.conf`，说明当前系统可能不使用该字段生成，或 DHCP/networking 服务后续仍把路由器 DNS 写回 resolvconf。

优先验证链路：

1. 查看当前 resolver 最终配置：`cat /etc/resolv.conf`
2. 直接指定 DNS 解析：`nslookup github.com 8.8.8.8`
3. 使用当前系统 DNS 解析：`getent hosts github.com`
4. 查看 DHCP 客户端配置是否真正写入：`grep -n "domain-name-servers" /etc/dhcp/dhclient.conf`
5. 重启获取租约的服务或重新获取 DHCP，而不是只重启 `resolvconf`。

---

## 关键知识点

- “能 ping IP，但不能访问域名”通常表示 IP 层可达、DNS 层失败。
- `/etc/resolv.conf` 是 glibc resolver 的最终配置入口，但在使用 `resolvconf`、NetworkManager、systemd-resolved 或 DHCP 客户端的系统上，它常常是生成文件。
- `supersede domain-name-servers 8.8.8.8, 114.114.114.114;` 应写入 `/etc/dhcp/dhclient.conf`，不能在 shell 中执行。
- 修改 DNS 配置后，要重启真正负责网络租约的组件，例如 `dhclient`、`networking`、`NetworkManager` 或对应网卡服务。
- 对嵌入式板卡，路由器下发的 DNS、IPv6 DNS、旧版发行版网络脚本和 resolvconf 同时存在时，最终结果以 `/etc/resolv.conf` 为准。

---

## 我的薄弱点

- 容易把 DNS 配置文件当作单一入口，需要先确认当前系统由谁生成 `/etc/resolv.conf`。
- 对 Debian/Ubuntu 派生系统中 `resolvconf`、`dhclient`、NetworkManager、systemd-resolved 的职责边界还需要继续熟悉。

## 收获

- 本次应把问题分层为：IP 连通正常，DNS 解析失败。
- 修复应优先让最终 `/etc/resolv.conf` 出现可用的 `nameserver`，再验证 `getent hosts github.com`，最后重试 `git clone`。
- 最小可靠路径是在 `/etc/dhcp/dhclient.conf` 中配置 `supersede domain-name-servers ...;`，然后重新获取 DHCP 租约或重启网络服务。

# 会话记录

## 基本信息

- 时间：2026-05-20
- 主题：Linux NVMe 控制器掉线与 ext4 journal abort 排查

---

## 问题

用户希望查看本机最近 3 次开机日志中的异常，并进一步分析：

- `Boot -2` 出现 `/home` 所在的 `nvme1n1p1` ext4 journal abort，并被重新挂载为只读。
- `Boot -1` 出现另一次 NVMe 读错误。
- 用户需要理解处理方案、相关内核参数含义，以及 `num_err_log_entries` 的意义。

---

## 分析

最近 3 次开机日志中，最关键的异常不是 ACPI 报错，而是 NVMe 控制器掉线导致块设备 I/O 失败。

核心证据：

```text
nvme nvme1: controller is down; will reset: CSTS=0xffffffff, PCI_STATUS=0x10
nvme nvme1: Does your device have a faulty power saving mode enabled?
nvme nvme1: Try "nvme_core.default_ps_max_latency_us=0 pcie_aspm=off pcie_port_pm=off" and report a bug
nvme nvme1: Disabling device after reset failure: -19
```

异常链路：

```text
NVMe 控制器掉线
-> 内核尝试 reset 控制器
-> reset 失败或读命令被 abort
-> 块设备返回 I/O error
-> ext4 journal 写失败
-> /home 被 remount read-only
```

SMART 结果显示：

```text
critical_warning: 0
media_errors: 0
num_err_log_entries: 4496
```

这说明当前没有直接证据证明 NAND 介质损坏。`num_err_log_entries` 较高是异常信号，但结合最新错误类型 `Invalid Field in Command`，更偏向 NVMe 命令、固件、驱动或电源管理兼容问题，而不是典型坏块。

---

## 关键知识点

- `journalctl --list-boots` 可以查看历史 boot；`journalctl -b -2 -p err..alert --no-pager` 可以提取某次 boot 的错误级别日志。
- 文件系统 journal abort 往往是结果，不一定是根因；要向上追到块设备、控制器、PCIe 链路和电源管理层。
- `media_errors = 0` 表示暂无 SMART 层面的介质/数据完整性错误，不等于系统完全健康。
- `num_err_log_entries` 是 NVMe Error Information Log 累计条目数，不是坏块数量。
- `nvme_core.default_ps_max_latency_us=0` 用于禁用或限制 NVMe APST 深度省电，常用于排查唤醒失败、控制器掉线。
- `pcie_aspm=off` 关闭 PCIe 链路级 ASPM。
- `pcie_port_pm=off` 关闭 PCIe Root Port/端口级电源管理。
- 内核日志已经给出 `Try "nvme_core.default_ps_max_latency_us=0 pcie_aspm=off pcie_port_pm=off"`，说明这些参数适用于当前 Linux 7.0.9 内核的排障场景。
- 修复顺序应是先备份，再稳定控制器/链路，再离线 `e2fsck` 检查 ext4。

---

## 我的薄弱点

- 容易把 ext4 journal abort 直接理解成文件系统本身损坏，而忽略上游 NVMe 控制器掉线。
- 对 NVMe SMART 字段的语义需要进一步熟悉，尤其是 `media_errors` 与 `num_err_log_entries` 的区别。
- 需要建立“日志链路追踪”思维：应用错误、文件系统错误、块设备错误、控制器错误、PCIe/电源管理错误要分层判断。

---

## 收获

- 本次问题更像 NVMe 电源管理/固件/链路兼容问题，而不是已经有明确坏块的 SSD 介质故障。
- 处理思路应避免直接执行破坏性修复：不要在控制器仍可能掉线时贸然 `fsck -y`。
- `num_err_log_entries` 要结合是否持续增长、错误类型、是否伴随 `controller is down` 和 `I/O error` 一起判断。

## 分析

首先消解了 MCP 的分类歧义：本文按 AI 领域的 Model Context Protocol 解释。MVC、MVP、MVVM 是应用内部 UI 分层模式；MCP 是 AI Host 连接外部数据、工具和工作流的开放协议，两者可以组合但不能互相替代。

三种 UI 模式没有根据 Activity、ViewModel 等类名比较，而是统一使用交互入口、依赖方向、UI 状态归属、更新方式、生命周期和测试方式。MCP 部分依据正式规范 `2025-11-25`，覆盖 Host/Client/Server、初始化能力协商、原语、stdio/Streamable HTTP 和安全边界。

---

## 关键知识点

- MVC 中 Controller 解释输入，经典 View 可以观察或读取 Model。
- MVP 中 Presenter 持有 View 接口并命令式更新，适合遗留 XML，但要处理 detach 和接口膨胀。
- MVVM 中 ViewModel 不持有具体 View，View 订阅 UiState，适合 Compose/Flow 和复杂异步状态。
- AndroidX ViewModel 不会自动处理进程死亡恢复。
- MCP Host 管理多个 Client，每个 Client 与一个 Server 维持 1:1 会话。
- MCP 的 Prompts、Resources、Tools 分别偏用户、应用和模型控制，但最终权限仍由 Host/用户决定。
- MCP 标准传输为 stdio 和 Streamable HTTP，旧 HTTP+SSE 已废弃。
- MVVM 可以管理 AI 应用页面状态，MCP 可以作为其外部工具集成边界。

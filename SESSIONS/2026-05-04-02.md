- 主题：解释并处理 `libvirtd` storage pool 路径缺失告警

---

## 问题

用户关注开机日志中的告警：

```text
libvirtd: cannot open directory '/home/zj970/work/ISO': No such file or directory
libvirtd: internal error: Failed to autostart storage pool 'iso-pool'
```

希望明确应该修正还是禁用该 storage pool。

---

## 分析

该问题来自 libvirt 的 storage pool 自动启动配置。`iso-pool` 被配置为开机自动启动，但它指向的目录 `/home/zj970/work/ISO` 当前不存在，因此 `libvirtd` 启动时尝试激活该池失败。

这不是 CPU/GPU 温度异常的直接证据，也不是系统级严重故障；它属于虚拟化环境配置残留或目录迁移后未同步更新。

---

## 关键知识点

- libvirt storage pool 是虚拟机镜像、ISO、磁盘文件的资源目录抽象。
- autostart pool 会在 `libvirtd` 启动时自动激活。
- 如果 pool 指向的目录不存在，libvirt 会记录告警并跳过该池。
- 修复方式有两类：恢复目录，或禁用/删除该 pool。

---

## 我的薄弱点

- 容易把开机日志中的所有 warning 都当成性能根因。
- 需要区分“配置噪声”“开机路径阻塞”和“真实温度/功耗根因”。

---

## 收获

- 明确 `iso-pool` 告警属于 libvirt storage pool 配置问题。
- 如果仍使用虚拟机 ISO 管理，应创建目录或改 pool 路径。
- 如果不使用该池，应取消 autostart 或删除 pool，减少开机日志噪声。

---

## 后续任务

- 使用 `virsh pool-list --all` 确认 `iso-pool` 状态。
- 如果保留该池，创建 `/home/zj970/work/ISO` 或重新定义池路径。
- 如果不再使用，执行 `virsh pool-autostart iso-pool --disable`，必要时 `virsh pool-undefine iso-pool`。

## 分析

用户已经在 FreshRSS、Open WebUI 等场景中使用过 Docker Compose，也接触过 Docker daemon、socket、端口映射和容器网络，但相关知识分散在具体任务记录里，缺少系统化的命令索引。

本次文档没有简单罗列命令，而是先建立镜像、容器、网络、卷和 Compose 项目的对象关系，再分别整理生命周期命令、典型部署流程、排障顺序和高风险清理操作。

本机验证环境为 Docker 29.6.2、Docker Compose 5.3.1，文档统一采用 Compose V2 的 `docker compose` 写法。

---

## 关键知识点

- Docker CLI、Docker daemon 和 Docker socket 是不同层次；CLI 可执行不代表 daemon 可用。
- 镜像是只读模板，容器是镜像的运行实例，数据卷独立于容器生命周期。
- `docker run` 创建新容器，`docker start` 启动已有容器。
- `docker compose exec` 在已有容器中执行命令，`docker compose run --rm` 创建一次性容器。
- `docker compose restart` 不会应用 Compose 配置变化，修改配置后应执行 `docker compose up -d`。
- `docker compose down` 默认不删除命名卷，`down -v` 会删除项目数据卷。
- 清理前应先运行 `docker system df -v`，再按容器、镜像、缓存和卷分类处理。
- Compose 项目部署前先运行 `docker compose config -q`，可以提前发现插值和结构错误。

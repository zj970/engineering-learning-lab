## 分析

当前源码是 Android 9 `pi-release` 时代 Launcher3，目录中同时存在普通 Launcher、Go、Quickstep 和 Quickstep Go 变体。技术文档不能只介绍 `Launcher.java`，也不能混入新版 Launcher3 架构，需要从构建 source set、进程入口、模型线程、UI 层级、状态机、拖拽和数据库七个方面建立完整开发地图。

源码确认当前版本没有自定义 `Application`。进程最早创建的组件是 `LauncherProvider`；`LauncherAppState` 在主线程按需初始化；`LauncherModel` 使用单独的 `launcher-loader` HandlerThread；`LoaderResults` 负责把数据绑定切回主线程。

---

## 关键知识点

- `Launcher` 是 HOME Activity，也是 `LauncherModel.Callbacks` 的主要实现者。
- `LauncherProvider` 同时承担进程早期初始化和 Workspace 数据持久化入口。
- Workspace 用户布局与 All Apps 应用列表属于两种数据：前者持久化，后者动态重建。
- `BgDataModel` 是 Workspace 内存模型，`AllAppsList` 是 All Apps 内存模型。
- `LauncherStateManager` 将状态应用给多个 `StateHandler`，普通版和 Quickstep 的 Handler 集合不同。
- `DragController` 负责命中和分发，`Workspace`、Folder 和按钮区域实现 `DropTarget`。
- 普通版与 Quickstep 通过 source set 提供同包同类名的 `UiFactory`，修改前必须确认产品变体。
- `favorites` 没有 SQLite 外键和唯一坐标约束，数据一致性主要由 Java 层维护。

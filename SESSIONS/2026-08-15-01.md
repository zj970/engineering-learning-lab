# 会话记录

## 基本信息

- 时间：2026-08-15
- 主题：Arch Linux AUR 安装企业微信时自动生成 debug 包导致文件冲突

---

## 问题

用户在 Arch Linux 上通过 `yay` 安装 `com.qq.weixin.work.deepin` 时，安装事务失败：

```text
com.qq.weixin.work.deepin-debug: /usr/lib/debug/.build-id/... exists in filesystem
owned by deepin-wine10-stable-debug
```

随后确认 `PKGBUILD` 本身没有显式声明 `-debug` 子包，但 `/etc/makepkg.conf` 中启用了：

```bash
OPTIONS=(strip docs !libtool !staticlibs emptydirs zipman purge debug lto)
```

---

## 分析

冲突不是企业微信主包文件冲突，而是 `makepkg` 根据全局 `OPTIONS` 自动生成了 `com.qq.weixin.work.deepin-debug` 包。

`strip` 会从二进制中剥离符号，`debug` 会把调试信息保存到独立的 debug 包中。当某些二进制内容与依赖包中的二进制调试 build-id 相同或重叠时，自动生成的 debug 包可能与已有的 `*-debug` 包争用 `/usr/lib/debug/.build-id/` 下的同一文件。

---

## 关键知识点

- `PKGBUILD` 没写 `pkgname=(xxx xxx-debug)`，也可能因为全局 `makepkg.conf` 的 `debug` 选项生成 `xxx-debug` 包。
- `debug` 选项需要结合 `strip` 才会生成单独调试符号包。
- 对单个 AUR 包临时禁用 debug，推荐使用独立 `makepkg.conf`，避免修改全局构建策略。
- 不建议用 `pacman --overwrite /usr/lib/debug/...` 解决包归属冲突。

---

## 我的薄弱点

- 容易把 `yay` 安装阶段的包冲突误判为 `PKGBUILD` 显式子包问题。
- 需要先区分“自动 debug 包”和“显式 split package debug 包”。

---

## 收获

- 看到 `xxx-debug` 包时，不应只看 `PKGBUILD` 的 `pkgname`，还要检查 `/etc/makepkg.conf` 中 `OPTIONS` 是否启用了 `debug`。
- 解决单个包的 debug 包冲突，优先临时关闭本次构建的 `debug` 选项。

---

## 后续任务

- 遇到 AUR 包安装冲突时，先用 `pacman -Qo <冲突文件>` 判断文件归属，再回到构建配置分析生成来源。

# 会话记录

## 基本信息

- 时间：2026-07-15
- 主题：电脑运行 Codex CLI，手机远程查看的项目选型

---

## 问题

用户想知道是否有比普通 SSH 更好的方式，尤其是 GitHub 上的项目，用于让电脑运行 Codex CLI，并在手机端远程查看或操作。

---

## 分析

Codex CLI 本质上是终端应用，因此最佳承载方式不是寻找专门的“Codex 手机端”，而是选择成熟的远程终端、远程 IDE 或远程桌面项目。核心判断标准包括：

- 会话是否能断线重连。
- 是否适合手机浏览器或手机 SSH 客户端。
- 是否避免把终端直接暴露到公网。
- 是否能保护代码仓库、OpenAI 凭据、Git 凭据等敏感信息。

---

## 关键知识点

- `tmux` 解决会话持久化问题，适合作为 Codex CLI 的底层运行容器。
- `Tailscale` 解决安全访问问题，比直接公网暴露 SSH 或 Web Terminal 更稳妥。
- `ttyd`、`WeTTY` 适合把终端变成网页，但必须配合内网穿透或认证保护。
- `code-server`、`openvscode-server` 适合手机端同时查看代码和终端。
- `MeshCentral`、`RustDesk` 属于远程桌面方案，适合需要完整控制电脑桌面的场景，但对纯 Codex CLI 来说偏重。
- `Sunwood-ai-labs/codex-remote-control-lab` 是更贴近 Codex 的专用方案：它用本地 Codex app-server 加一个 token 保护的 LAN 手机桥接 UI，让手机浏览器继续操作桌面上的 Codex 线程。
- 这类专用桥接方案比 `ttyd` 更像“Codex 手机控制台”，但仍要遵守它自己的安全边界：不要公开暴露桥接服务，不要泄露带 token 的 URL，外网访问优先使用 VPN、SSH 转发或 mesh network。

---

## 我的薄弱点

- 容易把“能远程访问”与“适合长期安全使用”混为一谈。
- 需要优先区分终端、IDE、远程桌面三类方案，而不是只按项目热度选择。

---

## 收获

- 对 Codex CLI 远程使用的推荐链路是：电脑运行 Codex CLI，`tmux` 保持会话，`Tailscale` 提供安全网络，手机通过 SSH 或 Web Terminal 查看。
- 如果需要在手机端查看代码，远程 IDE 比纯 Web Terminal 更合适。
- 如果只是查看 Codex 输出，远程桌面不是首选。
- 对于愿意接受实验性项目的用户，`codex-remote-control-lab` 可以作为优先试用方案；对稳定性、安全边界要求高时，仍应保留 `tmux + SSH/Tailscale` 作为兜底链路。

---

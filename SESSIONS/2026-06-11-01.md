# 会话记录

## 基本信息

- 时间：2026-06-11
- 主题：Open WebUI 连接 llama-server 的本地端口排查

---

## 问题

用户询问 `llama-server` 是否能和 Open WebUI 使用，并反馈执行：

```bash
curl http://127.0.0.1:8080/v1/models
```

返回：

```text
curl: (7) Failed to connect to 127.0.0.1 port 8080 after 0 ms: Could not connect to server
```

---

## 分析

`curl: (7)` 在这里表示 TCP 连接没有建立成功，最直接含义是 `127.0.0.1:8080` 没有可连接的服务。它还没有进入 OpenAI API 协议层，因此优先排查监听状态，而不是排查 Open WebUI 配置或模型推理参数。

排查顺序：

1. 确认 `llama-server` 进程是否已经启动。
2. 确认监听端口是否真的是 `8080`。
3. 确认监听地址是否包含 `127.0.0.1` 或 `0.0.0.0`。
4. 如果 Open WebUI 运行在 Docker 中，区分容器内 `localhost` 与宿主机 `localhost`。

---

## 关键知识点

- `llama-server` 可以通过 OpenAI-compatible API 接入 Open WebUI。
- `curl /v1/models` 连不上，说明问题在网络监听层，不是模型列表解析层。
- Open WebUI 连接本地 `llama-server` 时，Base URL 通常是：

```text
http://127.0.0.1:8080/v1
```

如果 Open WebUI 在 Docker 容器中，而 `llama-server` 在宿主机中，通常应使用：

```text
http://host.docker.internal:8080/v1
```

或通过 Docker 网络服务名访问。

---

## 我的薄弱点

- 需要区分“HTTP API 不兼容”和“TCP 端口没监听”这两类完全不同的问题。
- 遇到连接失败时，不应先改 Open WebUI 配置，而应先验证后端进程和端口。

---

## 收获

- 本地 LLM 服务接入 Web UI 时，先用 `curl /v1/models` 验证最小链路。
- `llama-server --host 0.0.0.0 --port 8080 --alias <name>` 更适合给 Web UI 或容器访问。

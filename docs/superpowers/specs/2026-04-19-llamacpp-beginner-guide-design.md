# llama.cpp 小白入门指南设计说明

**目标：** 编写一篇面向“有 Linux / 命令行基础，但不了解 `llama.cpp`”读者的入门文档，重点帮助读者建立 `llama.cpp` 的整体认知，并提供最小可执行示例。

**读者画像：**
- 会使用 Linux 终端
- 理解基本文件路径、环境变量、命令执行
- 不熟悉本地大模型运行体系
- 不清楚 `GGUF`、量化、`llama-cli`、`llama-server`、embedding 等概念

**范围：**
- 解释 `llama.cpp` 是什么
- 解释 `llama.cpp` 的主要组件和工具
- 解释模型类型、文件格式、量化与显存关系
- 解释 GPU/CPU 混合推理的基本思路
- 给出 chat / coder / embedding 的最小使用示例
- 解释 GUI / 服务化的基本使用方式
- 总结常见误区

**非目标：**
- 不写成面向完全零基础用户的 Linux 教程
- 不覆盖所有 `llama.cpp` 命令参数
- 不深入讲解向量数据库、RAG 工程实现细节
- 不围绕某一台机器写成纯实操复盘

---

## 1. 背景

当前仓库已经完成一轮从 Ollama 切换到 `llama.cpp` 的本地实践，并验证了三类模型：

- coder 模型
- chat 模型
- embedding 模型

说明本地链路已经跑通。但现有沉淀仍偏“会话过程记录”，缺少一篇系统性的说明文档，帮助后续快速回答这些问题：

- `llama.cpp` 到底是什么
- `llama-cli`、`llama-server`、`llama-embedding` 分别干什么
- `GGUF`、量化、`-ngl`、显存拟合是什么意思
- 为什么 chat 模型输出自然语言，而 embedding 模型输出一堆浮点数

因此，需要新增一篇面向有基础用户的“小白入门指南”，重点不是机械命令汇总，而是把整体体系讲清楚。

## 2. 方案比较

### 方案 A：工具导向型

按可执行程序组织章节：

- `llama-cli`
- `llama-server`
- `llama-embedding`
- `llama-server` Web UI

优点：
- 查命令方便
- 与实际使用动作贴近

缺点：
- 容易只会用命令，不理解整体体系
- 对初学者建立心智模型帮助有限

### 方案 B：概念导向型

按模型和概念组织章节：

- `llama.cpp`
- `GGUF`
- 量化
- embedding
- reranker
- server / GUI

优点：
- 体系感强

缺点：
- 太容易变成偏理论说明
- 缺少实操抓手

### 方案 C：分层导向型

按“从整体到组件、从概念到落地”组织：

1. `llama.cpp` 的定位
2. 主要组件
3. 模型类型与文件格式
4. 量化、显存与混合推理
5. 最小使用示例
6. GUI / 服务化
7. 常见误区
8. 推荐组合

优点：
- 同时兼顾认知和实操
- 更适合“有命令行基础但缺乏体系认知”的读者
- 结构清晰，后续也容易扩展

缺点：
- 需要控制篇幅，避免每层都写太深

**推荐：** 采用方案 C。  
原因：它最符合“理解体系为主，顺带给最小实操”的目标。

### 3.2 文档结构

#### 第一章：`llama.cpp` 是什么

目的：
- 让读者先建立“它是本地运行框架，不是模型本身”的概念

核心内容：
- `llama.cpp` 的角色
- 与“模型文件”之间的关系
- 为什么本地部署时经常会配合 `GGUF`

#### 第二章：常见组件和工具

目的：
- 让读者知道不同程序分别负责什么

核心内容：
- `llama-cli`
- `llama-server`
- `llama-embedding`
- 必要时简要提 `llama-server` 自带 Web UI

#### 第三章：模型类型与文件格式

目的：
- 让读者理解为什么需要不同模型

核心内容：
- chat / instruct 模型
- coder 模型
- embedding 模型
- reranker 模型
- `GGUF` 文件的作用

#### 第四章：量化、显存与混合推理

目的：
- 解释为什么 8GB 显存也能跑 7B 或更大的量化模型

核心内容：
- 量化的基本含义
- `Q4_K_M` 这类命名的直观理解
- `-ngl` 的作用
- GPU / CPU 混合推理的基本思路

#### 第五章：最小使用示例

目的：
- 让读者快速知道最小命令长什么样

核心内容：
- chat 模型示例
- coder 模型示例
- embedding 模型示例

要求：
- 只保留最小必要命令
- 不展开成完整安装手册

#### 第六章：GUI 与服务化

目的：
- 让读者知道除了 CLI 以外还能怎么用

核心内容：
- `llama-server`
- 浏览器访问本地 Web UI
- OpenAI 兼容接口的定位

#### 第七章：常见误区

目的：
- 优先消除最容易卡住新手的误解

拟覆盖内容：
- `embedding` 模型不是聊天模型
- `-n` 不是上下文窗口
- 下载词表 `.gguf` 不等于下载完整模型
- 编译成功不等于运行成功
- 动态库路径问题和 `PATH` 问题不是一回事

#### 第八章：一个最小推荐组合

目的：
- 让读者快速形成“一个能用的本地组合”

拟给出：
- 一个 coder 模型
- 一个 chat 模型
- 一个 embedding 模型

并说明三者职责分工。

## 4. 写作原则

- 先讲清角色，再给命令
- 只保留最小必要背景
- 不把文档写成长参数表
- 使用主动语态和现在时
- 对命令只解释“为什么需要”，不展开成 Linux 入门课

## 5. 风险与控制

### 5.1 风险

- 写得太理论，读者仍然不会用
- 写得太实操，体系感又不够
- 过度绑定当前机器环境，削弱通用性
- 把 embedding / reranker / chat 的职责混写

### 5.2 控制策略

- 每章都保留一个“这一层的目的”
- 命令示例只放最小必要示例
- 避免写入与某一台机器强耦合的目录细节
- 在“常见误区”中专门纠正本轮实践中真实遇到的问题
